## 2. Prompt and Solution Design

CampusAnswer explores a policy helpdesk that answers only from supplied local policy sections. The workflow classifies the question, retrieves relevant sections, supplies only those excerpts to the selected prompt/model, parses structured output, and verifies that cited quotations and answer text are present in the retrieved evidence. If evidence is missing, conflicting, or out of scope, the answer communicates that limitation rather than inventing a rule.

The implemented flow routes greetings to predefined responses, general knowledge to Gemini, and university-policy requests to category-aware retrieval over either the official-source index or the separately labeled fictional samples. Follow-ups use conversation history to resolve references; history is not treated as policy evidence. Policy citations are validated against the retrieved excerpts. If Gemini is not configured for a response that requires generation, the backend returns a service-unavailable error rather than simulating an AI answer.

Three prompt versions are included. V1 is the required Milestone 1 baseline. V2 adds classification and structured evidence handling. V3 strengthens exact quotation, conflict, currentness, unrelated and multiple question, prompt-injection, and confidence rules. The policy prompt versions are kept separate from the general-knowledge prompt. The workflow is documented by the prompt log and diagrams in `docs/diagrams/`.

**Output contract:** category, answer, citation list (document, section, exact quote), confidence, status, contact recommendation, execution mode, and prompt version.

## 3. Implementation

- **Frontend:** React, Vite, Tailwind CSS, Lucide React, and Firebase Google sign-in. Responsive pages cover overview, chat, policy library, executed evaluation, project information, and authenticated profile settings.
- **Backend:** Python, FastAPI, Pydantic, Firebase ID-token verification, protected profile and policy APIs, and administrator-allowlisted local uploads.
- **AI and retrieval:** Configurable Gemini generation plus local retrieval. Official sources are stored in a sparse SQLite index with document, date/year, URL, and page metadata. Fictional sample policies remain separate.
- **Safety checks:** exact source/document matching, quote containment, conservative answer verification, explicit unsupported/conflict handling, and clear separation between general answers and university policy.
- **Storage:** official indexes and local uploads are filesystem/local database resources; fictional sample policies are tracked text files. No claim is made that this local prototype is production deployment ready.

## 4. Demonstration and Testing

The test dataset has 18 distinct questions: 10 normal, 6 edge, and 2 invalid cases. It covers predefined greetings, general knowledge, official attendance conflict and citations, exam failure, a history-dependent follow-up, hostel rules and missing exact timing, fee deadlines, scholarships, absent sample-policy evidence, a fictional hostel conflict, ambiguous and mixed questions, currentness, and prompt injection. Each case is executed under V1, V2, and V3. Live Gemini-dependent cases are recorded as blocked if the service is not configured.

The recorded output in `test-data/demo-evaluation-results.json` was generated by `backend/run_evaluation.py`. In the recorded no-key run, **54 attempts** resulted in **30 passed, 0 failed, and 24 blocked**. Each version had 10 passed local checks and 8 blocked Gemini-required generations. The **100%** pass percentage is only among the 30 evaluable local checks; no inputs completed with Gemini for all three prompt versions. The run does not measure live-model quality or establish prompt-version superiority. See `MILESTONE2_EVIDENCE.md` for the verified feature audit, exact commands, limitations, and outstanding submission tasks.

Focused backend tests are in `backend/tests/test_engine.py`. Exact setup and run commands are in the root README.
