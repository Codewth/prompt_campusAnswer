## 2. Prompt and Solution Design

CampusAnswer explores a policy helpdesk that answers only from supplied local policy sections. The workflow classifies the question, retrieves relevant sections, supplies only those excerpts to the selected prompt/model, parses structured output, and verifies that cited quotations and answer text are present in the retrieved evidence. If evidence is missing, conflicting, or out of scope, the answer communicates that limitation rather than inventing a rule.

Three prompt versions are included. V1 is the required Milestone 1 baseline. V2 adds classification and structured evidence handling. V3 adds explicit boundaries for exact quotations, conflicting policies, unrelated and multiple questions, prompt injection, and confidence. The workflow is documented by the prompt log and diagrams in `docs/diagrams/`.

**Output contract:** category, answer, citation list (document, section, exact quote), confidence, status, contact recommendation, execution mode, and prompt version.

## 3. Implementation

- **Frontend:** React, Vite, Tailwind CSS, and Lucide React. Responsive pages cover overview, chat, policy library, executed evaluation, and project information.
- **Backend:** Python, FastAPI, and Pydantic. Local TXT/text-based PDF policy parsing, section retrieval, API endpoints, and local uploads.
- **AI:** Optional Gemini API with model configured by `GEMINI_MODEL`; credentials come from `.env` and are not committed. Without a key, deterministic lookup is clearly labeled demo mode.
- **Safety checks:** exact source/document matching, quote containment, conservative answer verification, explicit unsupported/conflict handling, and refusal for unrelated questions.
- **Storage:** sample policies are tracked fictional text files. Administrator-demo uploads are saved locally under ignored `backend/documents/`.

## 4. Demonstration and Testing

The test dataset has 13 distinct question strings spanning normal, edge, and invalid cases: attendance, examination eligibility, hostel timing, fees, deliberately conflicting documents, missing policy information, ambiguous/exception requests, unrelated questions, multiple questions, and prompt injection. Each input is executed against V1, V2, and V3 under comparable settings.

The recorded output in `test-data/demo-evaluation-results.json` was generated by `backend/run_evaluation.py`. On the recorded run (`2026-11-21T20:53:50Z`), deterministic demo lookup passed **39/39 runs (100.0%)**: V1 **13/13**, V2 **13/13**, V3 **13/13**. These are deterministic category/status/citation-presence checks, not live-model evaluations. Since prompt text does not alter deterministic lookup, these results do not establish prompt-version superiority.

Focused backend tests are in `backend/tests/test_engine.py`. Exact setup and run commands are in the root README.
